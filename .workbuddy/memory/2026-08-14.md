## 平台调整: Phala Cloud（第二轮）

用户实际部署平台是 **Phala Cloud**（TEE GPU 云）。经调研官方文档，Phala 有硬性限制：
- ❌ 不支持 `build.context` 路径引用
- ❌ 不支持外部 Dockerfile 引用
- ❌ 不支持 env_file、host bind volumes
- ✅ 必须用 `image:` 引用已推送到镜像仓库的预构建镜像
- ✅ 镜像必须 linux/amd64

### 最终方案（重新设计）

调整后的项目结构（Phala 兼容）：
- `docker-compose.yml` — 仅含 `image:` 字段（无 build），命名卷，环境变量内联
- `Dockerfile` — 镜像构建（本地或 CI 用）
- `app.py` / `requirements.txt` — 应用代码
- `build-and-push.sh` — 本地一键构建推送脚本
- `.github/workflows/build-and-push.yml` — GitHub Actions 自动构建推送（无需本地 Docker）
- `README.md` — 完整 4 步部署流程

### 部署流程（用户视角）
1. 用 GitHub Actions 或本地 Docker 构建镜像 → push 到 Docker Hub
2. 修改 docker-compose.yml 的 image 字段为 `用户名/minimax-h3-gradio:latest`
3. 粘贴到 Phala Dashboard 或用 `phala cvms create -c docker-compose.yml`
4. 访问 Phala 分配的 URL（端口 7860）

### 核心结论
"只能上传 docker-compose.yml" 在 Phala 上无法做到真正的"全自动单文件"——必须先有镜像仓库。这是 Phala 的硬性架构限制，非项目能绕过。
