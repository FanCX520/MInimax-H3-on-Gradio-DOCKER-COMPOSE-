## 平台调整: Phala Cloud（第二轮）

用户实际部署平台是 **Phala Cloud**（TEE GPU 云）。经调研官方文档，Phala 有硬性限制：
- ❌ 不支持 `build.context` 路径引用
- ❌ 不支持外部 Dockerfile 引用
- ❌ 不支持 env_file、host bind volumes
- ✅ 必须用 `image:` 引用已推送到镜像仓库的预构建镜像
- ✅ 镜像必须 linux/amd64

### 最终方案（重新设计）

调整后的项目结构（Phala 兼容）：
- `docker-compose.yml` — 仅含 `image:` 字段（无 build），命名卷，环境变量内联
- `Dockerfile` — 镜像构建（本地或 CI 用）
- `app.py` / `requirements.txt` — 应用代码
- `build-and-push.sh` — 本地一键构建推送脚本
- `.github/workflows/build-and-push.yml` — GitHub Actions 自动构建推送（无需本地 Docker）
- `README.md` — 完整 4 步部署流程

### 部署流程（用户视角）
1. 用 GitHub Actions 或本地 Docker 构建镜像 → push 到 Docker Hub
2. 修改 docker-compose.yml 的 image 字段为 `用户名/minimax-h3-gradio:latest`
3. 粘贴到 Phala Dashboard 或用 `phala cvms create -c docker-compose.yml`
4. 访问 Phala 分配的 URL（端口 7860）

### 核心结论
"只能上传 docker-compose.yml" 在 Phala 上无法做到真正的"全自动单文件"——必须先有镜像仓库。这是 Phala 的硬性架构限制，非项目能绕过。

## Gradio 兼容性修复（第四轮）

Phala 上线后，容器反复重启。错误日志显示：
- `TypeError: Video.__init__() got an unexpected keyword argument 'show_download_button'`
- `UserWarning: theme, css parameters have been moved from Blocks to launch() in Gradio 6.0`

### 原因
镜像中 pip 默认装的是 Gradio 6.x（最新版本），而代码按 Gradio 5.x 写。
- `show_download_button` 在 5.x 引入，6.x 移除
- `theme` 和 `css` 参数在 6.0 从 `gr.Blocks()` 移到 `launch()`

### 修复
1. 删除 `gr.Video(show_download_button=True)` 参数
2. 把 `theme=` 和 `css=` 从 `gr.Blocks()` 移到 `launch()` 方法
3. 提交并 push → GitHub Actions 重新构建（约 10 分钟）

## Gradio 6.x 兼容性第二轮（第五轮 - show_api 错误）

新错误：`TypeError: Blocks.launch() got an unexpected keyword argument 'show_api'`

### 根本原因分析
Dockerfile 用 `gradio>=5.0.0`，pip 默认装最新的 6.x，但代码按 5.x 写。
Gradio 6.0 的破坏性变更：
- `show_download_button` 被移除
- `show_api` 被移除
- `theme`, `css` 从 `Blocks()` 移到 `launch()`

1. `Dockerfile`: `gradio>=5.0.0` → `gradio==5.49.1`
2. `requirements.txt`: 同上
3. 恢复 5.x 代码（theme/css 在 Blocks、show_download_button 保留）

## Phala 持久化机制（重要）

通过研究官方文档确认：
- **Restart CVM**: 磁盘数据完全保留 ✅
- **Stop/Start (CPU)**: 磁盘保留 ✅
- **Stop/Start (GPU On-Demand)**: 磁盘删除 ❌
- **Delete CVM**: 磁盘删除 ❌

**用户的判断是对的**："反正容器不会主动删除"，所以模型下载一次就永久缓存。重启容器（不删磁盘）就能用缓存。

### 关键经济教训
- **不要 Stop** GPU CVM（On-Demand 计划下会删除磁盘）
- **不要 Delete + Create**（用户已花 100 刀学费）
- **应该用 Restart**（免费保留磁盘）
- 修复代码后：git push → Actions 重建 → Phala Restart
